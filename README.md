# Codex 自动继续（dsh-codex-429-nudge）

盯住 Codex 桌面应用，一旦它被上游 **429 Too Many Requests** 或者**额度用尽**卡住，就替你点那个恢复按钮。你切到别的会话去了，它会把任务那个会话找回来；同时开了好几个任务，它也会挨个翻一眼。

不用鼠标、不抢焦点，你在别处打字也不会被打断。给的是"人离开电脑时替你看着"这件事。

## 装到 DSH 里

1. 克隆下来：`git clone https://github.com/lchnistarmetrostar/dsh-codex-429-nudge`
2. 在 DSH 里让 AI 把这个目录装成插件（说一句「把 `<目录>` 装成插件」就行）
3. 进 **设置 → Codex 自动继续**，打开总开关

只需要 Windows 自带的 PowerShell，不用装任何东西。


## 它是怎么做到的

Codex 应用是 Electron 写的，界面元素对 Windows 的 **UI Automation**（系统级"读屏"接口）可见，**窗口最小化时也能读到**。所以：

1. 每隔一段时间读一次界面：有没有 429 报错、有没有恢复按钮、对话是不是在跑；
2. 判定"卡住"，三种都算：
   - **普通对话**：不在运行 + 有 429 报错 + 报错是最新一条（用元素顺序判断，不看坐标）；
   - **目标（Goal）模式**：界面上那条横幅写着「目标已停滞」或「已暂停的目标」。这种情况**不能**用报错顺序判断——目标暂停时 429 横条后面还挂着上一轮正常回复，比顺序会漏判（2026-10-25 就是这么白白放过一整夜）；
   - **额度用尽**：界面上出现「你已达到使用上限……升级套餐或充值额度……」。这不是 429，但对你来说是一回事：任务停了。同理不能按顺序判断。
3. 卡住了就按下面的顺序找东西点：

| 顺序 | 场景 | 点哪个 |
| --- | --- | --- |
| 1 | 普通对话 | 输入框右下角黑色圆钮，无障碍名就是「继续」 |
| 2 | 目标（Goal）模式 | 名叫「恢复目标」/「继续目标」的按钮 |
| 3 | 目标模式但名字对不上 | 按位置抓「目标已停滞」横幅右边那个 ▶ |
| 4 | 上面都没有 | 往输入框写"继续"，再点发送 |
| 5 | 连输入框都用不了 | 记原因 + 弹 Windows 通知告诉你 |

4. 点成功一次就扣一次预算。**Codex 中途恢复正常也不清零** —— 你要的是"我离开这段时间都替我盯着"，不是"连续失败次数"，所以恢复一次只花掉一次，剩下的还留着。

## 用之前要知道

- 只支持 **Windows**。
- 它不绕过 429。429 是上游额度/限流，插件只是把"重新发起请求"自动化；上游没恢复，点了还是 429。
- **额度用尽时点了也可能白点**（额度没恢复就还是会停）。插件会照常试，但更省事的做法是用「到点再试一次」定到额度重置的时刻，见后文。
- **锁屏、睡眠、待机都不是必要条件**（2026-10-25 实测：不锁屏、交流电下从不睡眠、整夜无待机，照样出现过"界面读不到内容"，见下一节）。
- 识别 Codex 靠三层：进程名含 `ChatGPT` → 窗口标题含该关键字 → 界面里有没有「和 Codex 一起工作」输入框。换版本/换装法导致认不出来时，改设置里的**窗口关键字**。

## 设置

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 启用 | 关 | 总开关，关掉就完全不动 Codex |
| 接管多久（档位） | 半小时 | 半小时 / 2 小时 / 半天 / 一天，一键设置间隔和次数 |
| 检查间隔 | 5 分钟 | 每多少分钟看一眼（0.5–60） |
| 最多重试 | 6 次 | 这一轮总共能点多少次（1–600），用完停手 |
| 窗口关键字 | ChatGPT | 进程名或窗口标题含它就当作 Codex，可用 `\|` 分隔多个 |
| 额外翻几个会话 | 5 | 每次额外检查几个"屏幕上看得见"的会话，0 = 只盯当前显示的那个 |
| 还要盯哪几个 | 空 | 另外指定要盯的会话标题，用 `;` 分隔，找不到就跳过 |
| 到点再试一次 | 空 | 睡到指定时刻再试一次（比如你知道额度几点重置），**这次不占预算** |
| 重新开始接管 | — | 预算用完、或想再盯一轮时点它，次数清零并重新计时 |

接管时长 = 检查间隔 × 最多重试，界面上直接算给你看，还会显示本轮开始时间和最晚结束时间。

## 同时开了好几个任务怎么办

Codex 一次只**显示**一个会话，而这个插件是靠"看界面"干活的，所以默认只能盯当前显示的那个。你把界面切去别处时，别的会话就算 429 了它也看不见。

所以有两个设置：

- **额外翻几个会话**（默认 5）：当前会话空闲时，它会去侧栏把"屏幕上看得见"的会话挨个点进去看一眼，卡了就点恢复，翻完切回你原来那个。每个约 1 秒，5 个大概 7 秒。**只在当前会话没在跑的时候才翻**，不会打断正在干活的。
- **还要盯哪几个**：写上你关心的会话标题（侧栏里显示的那个名字），用 `;` 分隔。滚出视野的会话它也能翻到。

两个都填就是"翻最近的 + 你点名的"合在一起去重。翻的间隔固定 10 分钟一次，不会每轮都翻。

## 到点再试一次

额度大概几点重置，你心里有数；那就别把次数耗在明知没用的时段，先睡到那个点再看一眼。

- 填法：`03:00`（下一个 3 点，今天过了就明天）、`+90`（90 分钟后）、`+3h`（3 小时后）
- 到点**一次**，试完自动取消，不会重复
- 这一下**不占预算**：预算用完了照样会试
- 常规的固定间隔不受影响，两者谁先到就按谁跑

## 额度用尽也会救

429 和「额度用尽」是两件不同的事，插件都管，但日志会分开写，因为该做的事不一样：

| | 429 / 限流 | 额度用尽 |
| --- | --- | --- |
| 界面长什么样 | `exceeded retry limit, last status: 429 Too Many Requests` | `你已达到使用上限。升级套餐或充值额度以继续，或稍后再试。` |
| 等一会儿会不会好 | 通常几分钟就好 | 得等额度重置（几小时 / 第二天） |
| 插件会做什么 | 点「继续」 | 同样点「继续」或发一条"继续" |
| 建议 | 正常盯着就行 | 用**到点再试一次**定到重置时间，别把次数耗在没用的时段 |

两点提醒：

- 模型选择器里那条短句「已达到使用上限」是**常驻提示**，插件不会把它当成卡住，只认上面那种完整长句。
- 额度用尽时 Codex 可能会**弹窗**（升级套餐 / 使用重置 / 添加额度），弹窗挡住按钮时插件会记成"没找到可点的按钮"并跳过这一轮，不会乱点你的弹窗。

它是给"额度要几小时后才回来"这种情况准备的：固定间隔继续按原节奏跑，这个负责在你猜的那个时间点上补一刀。

## 你切到别的会话去了，它会把任务那个会话找回来

Codex 一次只显示一个会话。**它只能盯"当前显示着的"那个**，所以如果你在它盯的会话跑着的时候切去别的会话（或者点了「新聊天」），它看到的就是一个空页面：窗口在、输入框也在，但对话内容一条都读不到，于是判"一切正常"，什么都不做。

**2026-10-25 凌晨就是这么空转了 7 小时**：02:19 那次 429 之后界面被切走了，插件从 02:41 起读到的全是空页面，一直瞎到 10:26。不是锁屏、不是睡眠、不是进程重启——系统日志和会话日志都证明了。

现在它这样做：

1. 只要读到一个**像样的会话**（有内容、且会话标题不是 `ChatGPT`），就把标题记进 `~/.dsh/codex-429-nudge/.last-session`；
2. 发现"内容 = 0 且会话标题 = `ChatGPT`"（说明停在新聊天页或别的空页面）时，去侧栏把记住的那个会话点回来，再读一遍；
3. **你正在打字就不抢**：输入框里有字时只记一行日志，不动界面（占位提示文字不算"有字"）；
4. 切回来还是读不到 → 退到第二道兜底：轻抖一下窗口逼它重绘；
5. 两道都没用 → 日志明说，`RESULT` 里 `blank:true`。

同一个问题 **30 分钟内只摇一次**，免得你停在新聊天页时窗口每 5 分钟抖一下。

两个实测出来的坑（写给以后看得懂代码的人）：侧栏里滚出视野的会话项，UIA 的 `Invoke()` 会**返回成功但界面根本不切**，必须先 `ScrollIntoView` 再重新取一次元素，才点得动；Codex 的输入框是 contenteditable，空着的时候 `ValuePattern.Value` 返回的是**占位文字**（`随心输入` / `和 Codex 一起工作`），不是空串。

## 救不回来会怎样

- 每次都写日志；
- 卡住但所有按钮和输入框都用不了时，弹一次 Windows 右下角通知（同样的原因 **30 分钟内不重复弹**，免得你人不在时一直响）。

## 日志

- 插件：`%USERPROFILE%\.dsh\codex-429-nudge\plugin.log`
- 脚本：插件目录下的 `nudge.log`
- 配置：`%USERPROFILE%\.dsh\codex-429-nudge\config.json`

## 手动试一次

```
powershell -NoProfile -ExecutionPolicy Bypass -File bin\codex-429-nudge.ps1 -Once -DryRun
```

`-DryRun` 只判定不动手，会打印一行 `RESULT {...}`，其中 `found`（认没认到窗口）、`stalled`（判定卡住没）、`acted`（点没点）、`failed`（没救成）、`blank`（界面读不到内容）就是插件读的东西。去掉 `-DryRun` 就会真的点。

状态行里还有两个诊断字段：`会话=[...]` 是当时在读哪个会话，`内容=N` 是读到的对话内容条数（正常界面几十上百，空界面是 0）。
